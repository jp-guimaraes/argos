# Argos documentation site

Source for the GitHub Pages site, built with [mdBook](https://rust-lang.github.io/mdBook/).
See [`.github/workflows/docs.yml`](../.github/workflows/docs.yml) for the build/deploy
pipeline.

## Structure

- `src/*.md` — book chapters. Each one is a single `{{#include}}` of a doc that already
  lives elsewhere in the repo (README.md, docs/architecture.md, CONTRIBUTING.md,
  CHANGELOG.md), so the site can never drift from the docs that already exist there —
  edit those files, not the includes.
- `theme/lang-switcher.{js,css}` — the language-switcher button injected into the menu
  bar (mdBook has no built-in one). Its `LANGUAGES` map must stay in sync with the
  `LANGUAGES` env var in `.github/workflows/docs.yml` and with `po/*.po` below.
- `po/*.po` — translations, one file per non-English language (see below).

## Previewing locally

```sh
cargo install mdbook mdbook-i18n-helpers --locked  # one-time
mdbook serve docs-site --open                      # English, live-reloading
```

To preview a translation, build it to its own directory instead (`serve` doesn't apply
the gettext preprocessor the way `build` does across a directory tree the switcher can
jump between):

```sh
MDBOOK_BOOK__LANGUAGE=pt-BR mdbook build docs-site -d book/pt-BR
```

## How the translations work

Uses [mdbook-i18n-helpers](https://github.com/google/mdbook-i18n-helpers) (the same tool
behind the official [Comprehensive Rust](https://google.github.io/comprehensive-rust/)
course): source strings live in English in `src/*.md` as usual, and each language gets a
gettext `po/<lang>.po` file mapping English strings to their translation. A string with
no translation yet (or an empty `msgstr`) falls back to English automatically — a
partially-translated chapter is expected, not broken.

**Updating translations after an English doc changes:**

```sh
# 1. Re-extract the English strings into a fresh template:
cd docs-site
MDBOOK_OUTPUT='{"xgettext": {}}' mdbook build -d po
# 2. Merge the new/changed strings into each translation (keeps existing msgstrs):
msgmerge --update po/pt-BR.po po/messages.pot
# 3. Fill in the new/fuzzy entries in po/pt-BR.po by hand, then build to check:
MDBOOK_BOOK__LANGUAGE=pt-BR mdbook build -d book/pt-BR
```

**Adding a new language** (example: `fr`):

```sh
cd docs-site
MDBOOK_OUTPUT='{"xgettext": {}}' mdbook build -d po
msginit -i po/messages.pot -l fr -o po/fr.po
```

Then translate `po/fr.po`, add `"fr"` to `LANGUAGES` in
`.github/workflows/docs.yml`, and add `fr: "FR"` to the `LANGUAGES` map in
`theme/lang-switcher.js`.

`po/messages.pot` itself is regenerated by the commands above and is not committed
(`.gitignore`) — only the translated `po/*.po` files are source of truth.
